This is a **major strategic improvement**, but the screenshots show that the new creation flow and the actual workspace are currently telling two different stories.

The front half now says:

# Message to the developer

## Kontra Runtime Generalization — Required Follow-Up

The new universal workspace creation flow is strong and reflects the intended strategy. However, the active workspace still falls back to the legacy CRE configuration after launch.

This must be corrected before we consider the universal transaction architecture complete.

### The core rule

Once a user selects a template, generates a workflow with AI, or starts blank, the active workspace must render entirely from that workspace’s saved Workflow Pack.

The room must not fall back to hardcoded CRE roles, documents, stages, terminology, risk fields or completion requirements.

The Workflow Pack selected and approved during creation must become the single source of truth for the live workspace.

---

## 1. Persist the generated workflow correctly

When the user reviews AI suggestions and launches the workspace, persist the final edited configuration as a workspace-specific snapshot containing:

```ts
type WorkspaceConfiguration = {
  workspaceId: string;
  source: "template" | "ai" | "blank" | "custom_pack";
  transactionType?: string;

  roles: WorkspaceRole[];
  documents: WorkspaceDocumentRequirement[];
  stages: WorkspaceStage[];

  terminology?: WorkspaceTerminology;
  metadataSchema?: WorkspaceFieldDefinition[];
  intelligenceModules?: string[];

  createdAt: string;
  configurationVersion: number;
};
```

The launched room must retrieve and render this saved configuration.

Do not reload the original CRE pack based on legacy property fields, route defaults or missing pack identifiers.

---

## 2. Fix the HVAC workspace shown in production

The AI-generated HVAC workspace included roles such as:

* Workspace Owner
* Financial Advisor
* Legal Counsel
* Operations Manager
* HR Representative

It included documents such as:

* NDA
* Letter of Intent
* Financial Statements
* Tax Returns
* Employee Contracts
* Lease Agreements
* Equipment Inventory
* Insurance Policies
* Customer Contracts
* Business Plan
* Closing Documents
* Audit Reports

And stages such as:

* NDA
* Letter of Intent
* Due Diligence
* Negotiation
* Closing

Those exact reviewed items should appear in the launched workspace.

Instead, the workspace currently displays the CRE checklist, CRE roles and CRE stages. This indicates the creation configuration is not being consumed by the room page.

Please trace the complete data flow:

```text
AI generation
→ user customization
→ saved workspace configuration
→ workspace initialization
→ live checklist
→ invite panel
→ progress tracker
→ risk/intelligence modules
→ verified package
```

Confirm that every component receives the same workspace configuration rather than importing static CRE defaults.

---

## 3. Make every live component pack-driven

The following sections must derive their content from the saved workspace configuration.

### Header

Currently:

* Commercial
* Owner / Borrower
* CRE background image

Instead:

* Display the generated transaction type, such as `Business Acquisition`
* Display the actual owner role, such as `Workspace Owner`
* Use a neutral workspace visual by default
* Allow a template-specific visual only when the relevant pack supplies it

### Setup Checklist

Currently hardcoded:

> Send links to your Lender / Underwriter, Inspector, Insurance Broker, Attorney.

Instead generate setup messaging from the actual roles:

> Invite the 4 required participants configured for this workspace.

Or:

> Invite your Financial Advisor, Legal Counsel, Operations Manager and HR Representative.

Never reference parties that are not in the workspace.

### Document Checklist

Render only the workspace’s saved document requirements.

Do not inject:

* Rent Roll
* T-12
* ALTA Survey
* Environmental Report
* Title Commitment

unless the selected configuration contains them.

### Invite Panel

Render only configured roles.

Do not inject:

* Lender
* Inspector
* Insurance Broker
* Servicer
* Franchisor

unless they exist in the workspace configuration.

### Transaction Progress

Render the configured stages in their saved order.

For the HVAC example, it should show:

```text
NDA → Letter of Intent → Due Diligence → Negotiation → Closing
```

It should not revert to the CRE defaults.

### Party Status

Generate party cards from configured roles only.

### Completion and readiness logic

The next-stage button and readiness state must evaluate the configured requirements for the current stage—not legacy CRE requirements.

## 4. Replace the fixed property-risk form

The current Risk Assessment section remains fully CRE-specific:

* Property Name
* Property Type
* Units / Sq. Ft.
* Asking Price
* Cap Rate
* Occupancy

This component should not appear in an HVAC business acquisition.

Replace it with a schema-driven transaction profile.

Example:

```ts
type WorkspaceFieldDefinition = {
  id: string;
  label: string;
  fieldType:
    | "text"
    | "number"
    | "currency"
    | "percentage"
    | "date"
    | "select"
    | "multiselect";
  required: boolean;
  options?: string[];
  category?: string;
  source: "template" | "ai" | "user";
  sortOrder: number;
};
```

For a business acquisition, suggested fields might include:

* Business Name
* Industry
* Transaction Value
* Annual Revenue
* EBITDA
* Employee Count
* Number of Locations
* Buyer Structure
* Financing Type
* Target Closing Date

For a CRE transaction, the CRE pack may still provide:

* Property Type
* Units
* Square Footage
* NOI
* Cap Rate
* Occupancy

For a blank or custom transaction, show a generic Transaction Details section or let the owner add fields.

The core platform must never assume that the underlying subject is real estate.

## 5. Make intelligence modular

The universal core should provide:

* Missing-item detection
* Participant status
* Expiration tracking
* Duplicate detection
* Cross-document inconsistency checks
* Approval tracking
* Open-dependency tracking
* Activity and audit history

Transaction-specific intelligence must be activated by the pack.

Example:

```ts
intelligenceModules: [
  "universal_document_verification",
  "business_financial_analysis",
  "employee_contract_review",
  "customer_concentration_review"
]
```

A CRE workspace may activate:

```ts
[
  "universal_document_verification",
  "cre_financial_analysis",
  "insurance_compliance",
  "property_due_diligence"
]
```

Do not show property metrics in a business acquisition merely because the legacy risk component exists.

---

## 6. Make compliance configuration-driven

The current Compliance Status still requires:

* Purchase Agreement
* Financial Statements
* Title / Ownership Documents

That requirement must come from the workspace checklist rather than a global static list.

Also, use careful language.

Instead of:

> Compliance Status

consider:

> Requirement Status

or:

> Workspace Readiness

“Compliance” can imply that Kontra has established legal or regulatory compliance. Kontra should report whether the owner-configured requirements are complete—not whether the transaction is legally compliant.

Recommended copy:

> 8 of 12 configured requirements complete.

And:

> Based on the requirements configured for this workspace.

---

## 7. Finish the language migration

Search the complete codebase and replace legacy universal strings where appropriate:

* `deal progress` → `transaction progress`
* `deal health` → `transaction health`
* `deal stage` → `transaction stage`
* `deal room` → `workspace`
* `property name` → dynamically configured label
* `owner / borrower` → configured owner role
* `Verified Asset Package` → `Verified Transaction Package`
* `commercial` → configured transaction type
* `closing` → final configured stage where applicable

Do not globally remove “deal” or CRE language from industry-specific packs. The goal is to remove it from the universal core.

---

## 8. Fix activation-page instructions

The activation screen currently says:

> Upload your financials, rent roll, purchase agreement, and inspection report.

That is incorrect for a custom HVAC transaction.

Make activation instructions generic and dynamic.

Recommended universal copy:

### Invite the participants

Send each configured participant a secure, role-specific invitation.

### Add the required documents

Upload or request the documents configured for this workspace. Kontra will organize and analyze eligible files as they arrive.

### Track the transaction

Monitor requirements, participant activity, open dependencies and progress through your configured stages.

---

## 9. Verified Transaction Package

The package title has been updated, but the failure state still says:

> Failed to generate Verified Asset Package.

Update every state and backend response to the new name.

The generated package should derive from the actual configuration and include:

* Transaction overview
* Workspace configuration version
* Configured participants
* Final document index
* Document hashes
* Requirement statuses
* Stage history
* Approvals
* Verification findings
* Activity audit trail
* Completion date
* Asset information only when applicable

Do not require property metadata to generate a Verified Transaction Package.

---

## 10. Suggested-item library

The new **Browse suggested items** control is good. Confirm that:

* Suggestions are optional
* Users can search all categories
* Users can create an entirely custom item

* Removing an item affects only that workspace

# Acceptance test

Use this exact test before deployment:

### Input

> I am acquiring a 15-location HVAC company. The seller is an individual owner. We have signed an LOI and are entering due diligence. The company has employees, customer contracts, equipment, leased locations and a lender.

### Expected result

The launched workspace should:

* Identify itself as a business acquisition or custom private transaction
* Show a neutral or business-relevant header
* Use `Workspace Owner`, not `Owner / Borrower`
* Display only the reviewed AI-generated roles
* Display only the reviewed AI-generated documents
* Use the reviewed stages
* Show business-relevant transaction fields
* Show no rent roll, T-12, ALTA, Phase I, cap rate, occupancy or multifamily fields
* Generate invitation cards only for configured roles
* Calculate readiness from configured requirements
* Generate a Verified Transaction Package without requiring property data

This test should pass from workspace creation through the live room and final package.

## My overall assessment

The strategic move is correct, and the new setup experience is substantially stronger. The AI review screen especially starts to make Kontra feel like a platform rather than a predefined deal-room product.

But the brief currently overstates the production status when it says:

> “The core platform is transaction-agnostic.”

Based on the screenshots, the more accurate status is:

> **The workspace creation architecture is now transaction-agnostic, while the live workspace is still partially dependent on the legacy CRE runtime.**

That is not a failure. It is simply the final and most important migration layer. Once the live room renders completely from the saved Workflow Pack, the platform shift becomes real rather than primarily presentational.
