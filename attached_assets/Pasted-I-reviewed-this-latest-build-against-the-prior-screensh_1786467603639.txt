I reviewed this latest build against the prior screenshots and the changes we were trying to achieve. **This version has regressed in a few places.** I would not move to upload testing quite yet.

The biggest issue is that the developer appears to have partially reverted to an older configuration.

### What I see now

**1. Transaction Readiness is still not fixed.** It still shows **8% / Needs Attention**, while directly underneath it says **0 of 30 required fields confirmed**. The old description is also still there: “Operational readiness across documents, workspace facts, activity, and compliance signals.”

So the primary logic correction from the last round was not implemented.

**2. The NDA contradiction is still present.** The room says **NDA Signed** at the top and in the lifecycle, while Documents says **Non-Disclosure Agreement — Missing**. There is also no “evidence missing” or “unsupported” indicator next to NDA Signed.

So that requirement also wasn't implemented.

**3. Role terminology regressed.** We're back to:

* Deal Coordinator
* Buyer Representative
* Seller Representative

instead of the simpler Buyer/Seller model from the prior iteration. More importantly, the owner is again labeled **Deal Coordinator**, despite being tagged Owner.

I would use **Deal Owner** for the creator, and **Buyer / Seller / Legal Advisor / Financial Advisor** for participants. “Representative” should only exist when the workflow specifically needs a representative role.

**4. Lifecycle changed to `LOI Submitted`.** This is better than “LOI Sent,” but I still prefer **LOI Executed** if the lifecycle is intended to represent completed milestones:

**NDA Signed → LOI Executed → Due Diligence → Financing → Closing**

If the intent is instead to track process states before acceptance, `LOI Submitted` is defensible. This isn't a blocker.

**5. Documents actually looks pretty good.** I would leave this layout alone. Required/Missing, responsible party, Upload and Request all coexist clearly. Don't redesign this screen again.

**6. Settings needs attention.** The settings page itself is clean, but it currently contains only:

* Deal Room Name
* Transaction Value
* Target Closing Date
* Notes

That's really **Transaction Details**, not “Settings.”

And there's a more important architectural opportunity here: **Transaction Value and Target Closing Date are exactly the type of facts that should feed the Transaction Record.**

If I enter:

> Transaction Value: $25,000,000
> Target Closing Date: December 15, 2026

Kontra should create/update those structured facts with a provenance such as:

> Source: Deal Owner input
> Status: User provided

That would legitimately increase Transaction Readiness.

This is exactly why the readiness number should be based on structured facts rather than miscellaneous activity.
