FINAL KONTRA DEAL ROOM RESTRUCTURE — FOLLOW THIS SPEC EXACTLY

IMPORTANT:
Do not redesign the product beyond these instructions.
Do not introduce new tabs, workflows, dashboards, forms, stages, fields, or features unless explicitly requested below.
Do not remove existing backend functionality that may be useful later.
This is primarily a UX / information architecture restructuring for launch.

We are done iterating randomly on the Deal Room.

PRODUCT PRINCIPLE

Kontra is an AI-powered transaction workspace that organizes a live transaction into a structured, evidence-backed record.

As the transaction progresses, that same record automatically becomes increasingly ready for future digital-asset / tokenization preparation.

The user should NOT have to run a separate "tokenization workflow."

The intended product loop is:

CREATE ROOM
→ INVITE PEOPLE
→ UPLOAD / REQUEST DOCUMENTS
→ KONTRA AI EXTRACTS TRANSACTION FACTS
→ PARTICIPANTS CONFIRM / CORRECT INFORMATION
→ STRUCTURED TRANSACTION RECORD GROWS
→ DIGITAL ASSET READINESS INCREASES
→ DIGITAL ASSET HANDOFF PACKAGE CAN EVENTUALLY BE PREPARED

This concept must drive the entire UX.

The Deal Room should feel extremely simple.

2. OVERVIEW — PURPOSE
==================================================

The Overview is NOT another checklist.

The Overview should answer four questions immediately:

1. What transaction is this?
2. What needs my attention right now?
3. What does Kontra know about the transaction?
4. How prepared is this transaction for future digital-asset/tokenization use?

The Overview should be substantially cleaner than the current version.

==================================================
3. OVERVIEW SECTION 1 — TRANSACTION SNAPSHOT
==================================================

Keep the existing Transaction Snapshot card at the top.

Display:

Transaction name
Transaction type
Current stage
Target closing date, if known
Transaction value, if known
Asset/company, if known
Primary party / buyer, if known

Do not show unnecessary empty metrics.

If information has not been collected yet, use a subtle "Not recorded" state.

Do NOT fill the page with empty statistics.

Keep the stage indicator if it is actually based on transaction data.

Do not invent transaction stages.

==================================================
4. OVERVIEW SECTION 2 — WHAT NEEDS ATTENTION
==================================================

Replace the current fragmented experience of:

Next Actions
AI Findings
Issues & Exceptions

with ONE intelligent operational section:

"WHAT NEEDS ATTENTION"

Subheading:

"Kontra prioritizes the items currently moving or blocking this transaction."

This should be a dynamic prioritized feed.

Possible items include:

- Document needs to be uploaded
- Document needs to be requested
- Participant needs to be invited
- Extracted fact needs confirmation
- Conflicting information needs review
- Missing transaction information
- New AI finding
- Potential issue or exception
- Participant response needed

Each item should clearly explain:

WHAT happened / is missing
WHY it matters
WHAT the user can do next

Example:

Title Report
Needed to confirm ownership and existing encumbrances.

[Upload] [Request]

Another example:

Purchase price requires confirmation
Kontra extracted $12,500,000 from the Purchase Agreement.

[Review]

Do not show separate giant empty AI Findings and Issues cards.

If there are no meaningful findings/issues, do not waste screen space telling the user repeatedly that nothing exists.

For a brand-new room, show a simple useful empty state:

"Start building the transaction record"

Upload the first document or invite a participant. Kontra will organize the transaction as information enters the room.

[Upload document] [Invite participant]

==================================================
6. HOW DIGITAL ASSET READINESS WORKS
==================================================

The readiness system should consume the SAME underlying structured transaction data Kontra is already collecting.

For example:

A Purchase Agreement may contribute:

buyer
seller
purchase price
asset identity
closing terms
jurisdiction

A Title Report may contribute:

ownership
liens
encumbrances
legal description

Financial Statements may contribute:

revenue
expenses
NOI
financial history

Participant confirmations may strengthen confidence in extracted information.

Therefore:

DOCUMENTS ARE INPUTS.

STRUCTURED FACTS ARE THE RECORD.

DIGITAL ASSET READINESS IS AN OUTPUT OF THAT RECORD.

Do not create three separate systems.

The architecture should conceptually be:

Document / Participant Input
↓
AI Extraction
↓
Structured Transaction Fact
↓
Source Evidence
↓
Confirmation / Correction
↓
Transaction Record
↓
Digital Asset Readiness

This is extremely important.
