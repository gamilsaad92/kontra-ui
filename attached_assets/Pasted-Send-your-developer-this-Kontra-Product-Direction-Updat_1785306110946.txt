## Kontra Product Direction Update

We are evolving Kontra from a platform limited to predefined CRE and business-acquisition workflows into a **customizable transaction workspace for any private transaction**.

This is not a complete rebuild. The existing workflow-pack architecture, document analysis, invitations, verification log, activity timeline, transaction risk, and closing flow should remain. The main change is that roles, documents, stages, and requirements must become fully configurable by the workspace owner.

### Core product principle

Kontra provides the transaction infrastructure, suggested templates, AI assistance, document coordination, and verification tools.

Kontra should **not determine the complete legal or due-diligence requirements for a transaction**. Templates are starting points only. The workspace owner and their professional advisers control the final checklist, participants, stages, and requirements.

---

# Phase 1: Workspace creation

Replace the current template-only creation flow with three options:

### 1. Start from a template

Keep:

* Business Acquisition
* CRE Acquisition
* Fundraising

Templates must be fully editable after selection.

The user must be able to:

* Add, remove, rename, and reorder roles
* Add, remove, rename, and reorder documents
* Mark documents required or optional
* Assign each document to a role
* Enable or disable AI analysis for each document
* Add, remove, rename, and reorder stages
* Change which roles are required
* Add custom roles and documents

Display this copy:

> Templates are suggested starting points. Review and customize the workspace with your legal, financial, and transaction advisers.

### 2. Build with AI

Ask:

> Describe the transaction you are coordinating.

Example:

> I am acquiring a 15-location HVAC company.

AI should suggest:

* Workspace name
* Roles
* Document checklist
* Transaction stages
* Required versus optional items
* Which documents should receive AI analysis

Show the suggestions before creating the workspace.

Actions:

* Accept all
* Edit suggestions
* Remove individual suggestions
* Add custom items
* Create workspace

The AI-generated workflow must include this notice:

> AI-generated suggestions may not include every document, approval, participant, or legal requirement. Review the workspace with qualified advisers before use.

### 3. Start blank

Create a workspace with no predefined transaction-specific content.

The owner manually adds:

* Roles
* Documents
* Stages
* Tasks
* Requirements

# Phase 2: Rebuild the checklist as editable components

The current Due Diligence Checklist should no longer be treated as fixed.

Each checklist item should be stored as a configurable object with fields similar to:

```ts
type ChecklistItem = {
  id: string;
  workspaceId: string;
  name: string;
  description?: string;
  category?: string;
  assignedRoleId?: string;
  stageId?: string;
  required: boolean;
  aiAnalysisEnabled: boolean;
  verificationEnabled: boolean;
  dueDate?: string;
  sortOrder: number;
  status: "missing" | "requested" | "uploaded" | "under_review" | "approved" | "waived";
  createdBy: "template" | "ai" | "user";
};
```

The owner should be able to edit the checklist inside the active workspace, not only before launch.

Add:

* `+ Add document`
* `Browse suggestions`
* `Create custom document`
* Drag-and-drop reordering
* Edit
* Duplicate
* Delete
* Mark optional
* Assign role
* Move to category
* Move to stage

# Phase 3: Add a suggestion drawer

Add a button above the checklist:

> **Browse suggested items**

This opens a searchable side panel or modal.

Suggested categories may include:

* Corporate and ownership
* Financial
* Legal
* Tax
* Operations
* Employees
* Insurance
* Intellectual property
* Regulatory
* Environmental
* Real estate
* Financing
* Closing

Users can select multiple suggestions and click:

> Add selected items

Also include:

> Create custom item

The suggestion library should be reusable across workflow packs, but selecting an item should copy it into the workspace so the owner can modify it without changing the global library.

Do not describe suggestions as universally required.

Use labels such as:

* Suggested
* Commonly requested
* Template item

Avoid:

* Required by Kontra
* Complete checklist
* All required documents

* Lender
* Inspector

The workspace owner must be able to:

* Add a custom role
* Rename a role
* Remove a role
* Choose whether the role uploads documents
* Choose whether the role is required
* Assign checklist items to the role
* Set role permissions
* Invite multiple people under one role where appropriate

Suggested role library:

* Seller
* Attorney
* Accountant
* Lender
* Investor
* Consultant

# Phase 5: Make stages configurable

The current stages:

* Uploading
* Under Review
* Approved
* Closing
* Funded
* Verified

must become defaults, not hardcoded universal stages.

Owners should be able to:

* Rename stages
* Add stages
* Remove stages
* Reorder stages
* Define stage-completion requirements
* Move the workspace manually when permitted

Examples of other possible stages:

* NDA
* Indication of interest
* LOI
* Due diligence
* Negotiation
* Regulatory review
* Signing
* Closing
* Post-closing

The interface should use **Transaction Progress**, not **Deal Progress**, where possible.

---

# Phase 6: Generalize the workspace language

Replace transaction-type-specific labels in the core platform.

Recommended changes:

* Deal Room → Transaction Workspace
* Deal Progress → Transaction Progress
* Deal Health → Transaction Health
* Share Deal → Share Workspace
* Deal room active → Workspace active
* Deal stage → Transaction stage
* Property Name → Asset or Transaction Name
* Property Type → Asset Type
* Owner/Borrower → Workspace Owner, unless supplied by the template

Do not remove industry-specific terminology from templates. CRE templates can still use property, rent roll, cap rate, and occupancy. Those fields simply should not appear in every workspace.

---

# Phase 7: Separate universal intelligence from template-specific intelligence

The core intelligence layer should work across all workspaces:

* Missing-document detection
* Duplicate-document detection
* Expiration tracking
* Participant-status tracking
* Cross-document inconsistency detection
* Approval tracking
* Activity audit trail
* Open-dependency detection
* Transaction-risk summary

Template-specific analysis should be modular.

Examples:

* CRE module: DSCR, NOI, cap rate, occupancy
* Business acquisition module: revenue, EBITDA, customer concentration, working capital
* Fundraising module: ownership, valuation, dilution, investor commitments

A custom workspace should not automatically show property-specific risk fields.

---

# Phase 8: Verified Transaction Package

Rename **Verified Asset Package** to:

> **Verified Transaction Package**

for now.

It should contain:

* Workspace summary
* Asset or transaction metadata
* Final participant roster
* Final document index
* Document hashes
* Approval history
* Stage history
* Verification findings
* Ownership information, when applicable
* Closing or completion date
* Full activity audit trail

Internally, keep the data model capable of producing a future **Verified Asset Package** when the workspace concerns an asset.

This package will become the foundation for future tokenization readiness, but tokenization should not appear in the current customer interface.

---

# Future-ready data model

Each workspace should optionally support an underlying asset record:

```ts
type AssetRecord = {
  id: string;
  workspaceId: string;
  name: string;
  assetType: string;
  description?: string;
  jurisdiction?: string;
  legalOwner?: string;
  ownershipStructure?: unknown;
  transferRestrictions?: unknown;
  identifiers?: unknown;
  metadata?: unknown;
};
```

This is not a blockchain feature.

It simply ensures that completed transactions can later produce structured, verifiable asset data without rebuilding the platform.

# Important legal and product language

Include a notice during workspace creation and checklist editing:

> Kontra provides workflow tools, suggested templates, and AI-assisted document coordination. Suggestions are not legal, financial, tax, underwriting, or compliance advice and may not include every requirement applicable to your transaction. The workspace owner is responsible for reviewing and configuring the workspace with appropriate professional advisers.

The product should never claim that:

* A checklist is legally complete
* A transaction is legally compliant
* All necessary documents have been included
* AI approval means professional approval
* The asset is legally eligible for tokenization

---

# Development priority

Please implement in this order:

1. Make template roles and checklist items editable.
2. Add blank workspace creation.
3. Add the suggested-item drawer.
4. Make stages editable.
5. Remove core CRE-specific fields from non-CRE workspaces.
6. Add AI workspace generation.
7. Generalize the Verified Transaction Package.
8. Add the optional internal asset record.

Do not redesign the entire workspace UI yet. Reuse the current components and make them data-driven and editable first.

The immediate goal is:

> A business broker, M&A adviser, attorney, investor, or other transaction owner can create a workspace for their own process without Kontra having to build or guarantee a complete industry-specific checklist.

---

My strongest recommendation is to make **template customization, blank workspaces, and the suggestion drawer** the first release. That gives you the strategic change without putting the entire platform back into development.
